# 每日簡報（由 Agent 排程呼叫）

emLek 本身不排程、不推播。由使用者的 Agent（例如 Codex 的定時執行）每天送出提示詞，呼叫 emLek 現有的搜尋，整理後通知使用者。不新增資料表或功能，決策見 [DECISIONS](DECISIONS.md) D30。

## 兩種提醒

| 類型 | 依哪個日期查 | 用途 |
|---|---|---|
| 到期提醒 | 事件日期（`event_time`）：今天與未來幾天 | 不漏掉期限、約定、預約 |
| 回顧提醒 | 存入日期（`created_at`）：兩週前（或自訂）那天 | 回想、複習，類似「去年今天」 |

## 前提與限制

- 排程必須在**本機**執行（雲端排程碰不到本機資料庫）；電腦關機時不會執行，下次執行請多查過去幾天補漏。
- 排程的 Agent 使用 MCP 唯讀模式（`emlek mcp --read-only`，工具清單根本沒有寫入工具，`max_sensitivity` 預設 medium，high 記錄的內文不會送出）。唯讀模式只限制 MCP，擁有 shell 的 Agent 仍可直接跑 `emlek hide` 等命令，因此排程另須用平台的唯讀沙箱或工具白名單（Codex 的唯讀沙箱選項；Claude Code 只允許 emlek 的唯讀 MCP 工具並禁用 Bash）。已用 Claude Code 2.1.316（Windows）實測：啟動時 `--tools ""`（不給任何內建工具），只用 `--allowedTools` 預先核准 emlek 的唯讀工具，即使要求它寫入也寫不進去；若保留 PowerShell 工具但不預先核准，無人看管時會被拒絕。對照組（預先核准 PowerShell）確實寫入，證明測試有效。Codex CLI 尚未測。
- 到期提醒依賴「存入時已填事件日期與標籤」（見 AGENT_RULES 的期限與約定）；漏填就查不到。這是盡力提醒，不是保證。
- 提醒內容會送到所用的 AI 平台；每次執行約耗 1–3 千 token（實測以題庫統計為準）。
- 完成判斷：原記錄有 `supplements` 連結且標籤「已完成」的新記錄（`linked_from`）即視為已完成，不再提醒。

## 提示詞範本

排程的日期欄位交給排程器填入：

> 今天是 YYYY-MM-DD。只讀取，不要儲存、修改或刪除任何紀錄。
> 1. 依事件日期查今天到未來 3 天的紀錄，並查過去 7 天內事件日期已到、標籤為待辦／截止／約定、但沒有「已完成」連結的紀錄。
> 2. 依存入日期查 14 天前當天記下的內容。
> 3. 條列標題、日期、記錄 ID。沒找到時說「記憶庫中沒有符合的紀錄」，不要說「今天沒事」。
