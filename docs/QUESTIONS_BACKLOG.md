# 題庫待補類別

從 [QUESTIONS](QUESTIONS.md) 移出。Agent 須在各里程碑開始前依「提醒時機」欄提醒使用者。

| 類別 | 內容 | 等什麼 | 提醒時機 |
|---|---|---|---|
| D. 組合與比較 | 已定義為 Q76–Q81（見 QUESTIONS），M7 實作時加入題庫與合成資料 | 標籤與別名（M7） | M7 實作時 |
| E. 含糊與追問 | 「上次那個想法」「那間店」：該問還是說明假設 | 版本與連結（M5）與多輪框架 | M5 完成後評估 |
| H. 多輪對話 | 追問、更正、分頁 | 多輪測試框架（尚無） | 與 E 同時 |
| 版本與推翻時間線 | Q08–Q10、Q22–Q23 的 AI 層版本 | M5 | M5 完成時一併加入 |
| 標籤與別名 | Q03、Q32、Q33、遠義詞題的重測 | M7 | M7 完成時重跑 Q20、Q48、Q49 |
| 敏感提示、匯入 | Q40–Q43 | M6、M8 | 各里程碑開始前 |
| 更多樣的合成資料 | 不同背景（學生、工程師、家長）、錯字俚語、日中英混寫段落 | 無 | 擴充題庫第二輪 |
| 資料品質情境 | 重複記錄、修正版本、隱藏的不出現、極長筆記、內文日期與事件日期不一致 | M5 | M5 完成時 |
| I. 規模與彙整 | 合成幾千筆，問會命中上千筆的彙整題（「我抽菸抽得兇嗎」「這兩年我去過哪些地方」）。驗收：AI 要說明只看了其中一部分或先縮小範圍，不可把前 20～100 筆當全貌；回傳大小與花費不得失控（單題 >$0.15 即不合格） | M5 回傳瘦身（過多先回筆數與分布） | M5 完成標準之一；開始 M5 時先建資料 |
| **凍結驗收集** | 使用者自己的真實問法（不含私人內容）；**從不用來調整規則**，只在驗收時跑，分數另外報告 | 使用者提供 20–30 句問法 | 使用者提供後立即建立 |

### 凍結驗收集的規則

調校用題與驗收用題必須分開：看過失敗再改規則、再用同一題驗證，會變成量身訂做（Q20 即是例子）。凍結集的題目一旦建立就不得為了提高分數而改規則；若失敗，只能記錄並評估是否需要新功能。使用者提供的只需要「問句」，不需要答案；答案由我用合成資料依問句的意思埋入。
