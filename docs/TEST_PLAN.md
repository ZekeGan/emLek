# 基本正確性測試計畫

寫測試或驗證時才讀。題庫（BENCHMARK）測「問得出答案嗎」，本檔測「資料本身會不會壞、規則有沒有守住」。全部使用合成資料；每條都要有可重現的自動測試，失敗要能指出是哪條不變式。工具：pytest 加 Hypothesis（隨機輸入）；「啟用」欄對應 DESIGN 開發順序的里程碑；每個里程碑完成時，已啟用的測試都要重跑。

## 不變式

| ID | 不變式 | 怎麼測 | 啟用 |
|---|---|---|---|
| T01 | 版本寫入後內容不可改、不可刪（清除除外） | 嘗試直接 UPDATE／DELETE 應被資料庫觸發器拒絕；API 無對應路徑 | M1 |
| T02 | 修改＝新增下一個 `version_no`，舊版逐位元組不變 | 存、改多次，逐版比對雜湊 | M5 |
| T03 | 原文往返一致：日文、中文、emoji、組合字元、換行、BOM、全半形 | Hypothesis 產生任意 Unicode，存入再取出逐位元組相同 | M1 |
| T04 | 搜尋正規化不改原文，只影響比對 | 全形與半形、大小寫的查詢都找得到，取回仍是原文 | M2 |
| T05 | 單次 `save` 全有或全無 | 在每個寫入點注入失敗（記錄、版本、連結、標籤、索引），確認不留半筆 | M1（之後各里程碑補新寫入點） |
| T06 | 行程被強制終止後資料庫可開、已提交的都在、未提交的都不在 | 子行程寫入中途殺掉，重開後 `integrity_check` 與筆數核對 | M1 |
| T07 | 兩個行程同時寫入不損壞、不遺失 | CLI 與 MCP 模擬同時存入，筆數與內容核對；忙碌時排隊或回 `BUSY` | M3 |
| T08 | 全文索引與資料一致 | 隨機存、改、隱藏、清除後，索引內容與資料表逐筆對得上 | M2（隱藏、清除情境於 M5、M9 補） |
| T09 | 事件時間：精度、時區、日界線正確 | 日精度不受時區影響；分精度保留偏移；跨日界線的範圍查詢 | M2 |
| T10 | 分頁：總筆數正確、不重複、不遺漏、游標穩定 | 查詢中途新增資料，頁間不重複不漏 | M2 |
| T11 | 輸入限制與錯誤碼 | 超長原文、過多標籤、空查詢、未知欄位都回對應 `INVALID_INPUT`，結束碼正確 | M1（標籤限制於 M7 補） |
| T12 | 隱藏：搜尋與讀取看不到、恢復後回來、衍生摘要同步失效；隱藏與 `unhide` 冪等；隱藏者不計入 `summary` 數字；推翻者被隱藏則被推翻者恢復為 `current`；`supersedes` 不傳遞隱藏效果、`derived`／`summarizes` 會 | 隱藏、恢復、檢查 `status`、`superseded_by` 與衍生記錄狀態、`summary` 筆數 | M5 |
| T13 | 推翻與支持：`superseded_by`、`linked_from`、`status` 正確還原 A→B→C→A（`current`／`superseded`／`reaffirmed`）；連到不存在、自己、隱藏者被拒；重複連結冪等；`amend` 的 `expected_version` 衝突、內文未變、隱藏中、`kind` 不可改、省略與 null 的差別；`current_only` 排除規則；`linked_from` 超過 50 條標 `truncated` | 建立四筆記錄與關係，逐一檢查各自回傳與錯誤碼 | M5 |
| T26 | 結果過多摘要：超過 50 筆才有 `summary`；`by_month` 加總等於總筆數減未標日期；超過 24 個月改 `by_year`；固定 `basis` 與 `note`；`get` 超過 8000 字元截斷並可用 `offset` 取完；舊欄位不變 | 以合成 120 筆跨 30 個月的資料查詢，對照 SQL 直接統計 | M5 |
| T14 | 語句與需真人終端機的命令（DESIGN 自訂語句清單）：標準輸入、輸出、錯誤輸出缺一個不是終端機就拒絕；AI 端對語句唯讀 | 管線、無終端機、子行程、只有輸入是終端機（如 Claude Code 的 PowerShell 工具）都應拒絕；PIN 不接受參數、環境變數、標準輸入；錯誤 PIN 被拒，連續錯誤鎖定 | M6 |
| T15 | 敏感提示：high 每次要 token，token 單次有效、綁內容、過期；medium 只問一次且可重開；規則掃描命中常見格式；`amend` 重新掃描取較高等級；AI 無法調低 `sensitivity`；`import` 略過含 high 的檔案並列出 | 逐項測；偽造或重用 token 被拒；醒目樣本（合成金鑰格式）命中 | M6 |
| T16 | 權限矩陣（每個操作×每個入口）：唯讀模式的工具清單根本沒有寫入、隱藏、清除工具；`max_sensitivity` 生效 | 以唯讀啟動，列出工具；對照核心權限表逐格驗證 | M3（每個里程碑重跑） |
| T17 | 標籤：正規化、別名、只往下展開（最多 3 層）、循環關係被拒 | 建立含環與深層的階層，檢查展開結果 | M7 |
| T18 | 標籤來源可分辨 user／ai；`#標籤` 解析不改原文 | 存含 `#標籤` 的文字，檢查來源欄與原文 | M7 |
| T19 | 備份往返：還原後逐筆相同；加密備份密碼錯誤被拒、檔案被竄改被拒 | 備份、還原到乾淨資料夾，比對匯出；改一個位元組後還原應失敗 | M4（加密於 M8 補） |
| T20 | 匯出無損且格式符合 v1；匯出再與資料庫比對 | 逐行驗證 JSONL 結構與筆數 | M4 |
| T21 | 匯入冪等；壞檔不影響其他檔；日期與標籤解析正確 | 重複匯入、混入壞檔與重複內容 | M8 |
| T22 | 清除後無殘留：版本、`body_norm`、索引、標籤關聯、衍生摘要、`tag_events` 明細；重新匯入同一檔案不復活；指向被清除版本的連結已移除 | 清除後掃描資料庫與 WAL 原始檔，確認找不到任何片段（已實測：不做 FTS `optimize`、checkpoint＋VACUUM 會殘留）；另在資料夾內放 `pre-migration/`、`before-restore`、`exports/` 副本，確認報告列出含片段的檔案且不被改動 | M9 |
| T23 | 清除流程：MCP 只有預覽沒有清除工具；`emlek purge` 需真人終端機與 PIN；答「否」或含糊不執行 | 以偽終端機驅動 CLI 逐種回答；MCP 工具清單檢查 | M9 |
| T24 | 遷移：舊版本資料庫升級後內容不變，失敗可回復 | 對每個 schema 版本建樣本庫，升級後比對 | M1 起每次新增遷移 |
| T25 | `doctor` 與啟動檢查：版本不足、同步資料夾、權限異常都有明確訊息 | 模擬各種環境（替換版本回報、放進同步路徑） | M1 |

## 效能與規模

1 千、1 萬、3.6 萬筆合成資料各跑一次：存入速度、全文查詢（3 字元以上）、1–2 字元短詞掃描、分頁、標籤展開、備份與還原耗時，並記錄資料庫檔大小。首次基準值出來後，與使用者約定可接受上限；不預先編造門檻。

## 執行方式

- 快速集（每次提交前）：T01–T04、T08–T11 的小資料版與型別檢查。
- 完整集（每步驟完成、發布前）：全部加規模測試。
- 故障注入（T05）與行程終止（T06）標記為 `slow`，不在快速集，但每個里程碑完成時必跑。
- 每個新功能或修正同批補對應測試；移除功能時同批更新或刪除。
