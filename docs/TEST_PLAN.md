# 基本正確性測試計畫

寫測試或驗證時才讀。題庫（BENCHMARK）測「問得出答案嗎」，本檔測「資料本身會不會壞、規則有沒有守住」。全部使用合成資料；每條都要有可重現的自動測試，失敗要能指出是哪條不變式。工具：pytest 加 Hypothesis（隨機輸入）；「啟用」欄對應 DESIGN 開發步驟。

## 不變式

| ID | 不變式 | 怎麼測 | 啟用 |
|---|---|---|---|
| T01 | 版本寫入後內容不可改、不可刪（清除除外） | 嘗試直接 UPDATE／DELETE 應被資料庫觸發器拒絕；API 無對應路徑 | 1 |
| T02 | 修改＝新增下一個 `version_no`，舊版逐位元組不變 | 存、改多次，逐版比對雜湊 | 1 |
| T03 | 原文往返一致：日文、中文、emoji、組合字元、換行、BOM、全半形 | Hypothesis 產生任意 Unicode，存入再取出逐位元組相同 | 1 |
| T04 | 搜尋正規化不改原文，只影響比對 | 全形與半形、大小寫的查詢都找得到，取回仍是原文 | 1 |
| T05 | 單次 `save` 全有或全無 | 在每個寫入點注入失敗（記錄、版本、連結、標籤、索引），確認不留半筆 | 1 |
| T06 | 行程被強制終止後資料庫可開、已提交的都在、未提交的都不在 | 子行程寫入中途殺掉，重開後 `integrity_check` 與筆數核對 | 1 |
| T07 | 兩個行程同時寫入不損壞、不遺失 | CLI 與 MCP 模擬同時存入，筆數與內容核對；忙碌時排隊或回 `BUSY` | 2 |
| T08 | 全文索引與資料一致 | 隨機存、改、隱藏、清除後，索引內容與資料表逐筆對得上 | 1 |
| T09 | 事件時間：精度、時區、日界線正確 | 日精度不受時區影響；分精度保留偏移；跨日界線的範圍查詢 | 1 |
| T10 | 分頁：總筆數正確、不重複、不遺漏、游標穩定 | 查詢中途新增資料，頁間不重複不漏 | 1 |
| T11 | 輸入限制與錯誤碼 | 超長原文、過多標籤、空查詢、未知欄位都回對應 `INVALID_INPUT`，結束碼正確 | 1 |
| T12 | 隱藏：搜尋與讀取看不到、恢復後回來、衍生摘要同步失效 | 隱藏、恢復、檢查 `superseded_by` 與衍生記錄狀態 | 3 |
| T13 | 推翻與支持：`superseded_by`、`linked_from` 正確還原 A→B→C→A | 建立四筆記錄與關係，檢查各自回傳 | 3 |
| T14 | 語句：AI 端唯讀；改 `purge` 類語句在非互動環境被拒 | 管線、無終端機、子行程呼叫都應拒絕 | 3 |
| T15 | 敏感提示：high 每次要 token，token 單次有效、綁內容、過期；medium 只問一次且可重開；規則掃描命中常見格式 | 逐項測；偽造或重用 token 被拒；醒目樣本（合成金鑰格式）命中 | 3 |
| T16 | 唯讀模式下寫入、隱藏、清除工具不存在或被拒 | 以唯讀啟動，列出工具並逐一嘗試 | 2 |
| T17 | 標籤：正規化、別名、只往下展開（最多 3 層）、循環關係被拒 | 建立含環與深層的階層，檢查展開結果 | 4 |
| T18 | 標籤來源可分辨 user／ai；`#標籤` 解析不改原文 | 存含 `#標籤` 的文字，檢查來源欄與原文 | 4 |
| T19 | 備份往返：還原後逐筆相同；加密備份密碼錯誤被拒、檔案被竄改被拒 | 備份、還原到乾淨資料夾，比對匯出；改一個位元組後還原應失敗 | 5 |
| T20 | 匯出無損且格式符合 v1；匯出再與資料庫比對 | 逐行驗證 JSONL 結構與筆數 | 5 |
| T21 | 匯入冪等；壞檔不影響其他檔；日期與標籤解析正確 | 重複匯入、混入壞檔與重複內容 | 5 |
| T22 | 清除後無殘留：版本、索引、標籤關聯、衍生摘要、`import_log` 關聯 | 清除後掃描全庫與全文索引，確認找不到任何片段 | 6 |
| T23 | 清除流程：預覽、確認碼、「否」不執行、含糊不執行 | 逐種回答測試 | 6 |
| T24 | 遷移：舊版本資料庫升級後內容不變，失敗可回復 | 對每個 schema 版本建樣本庫，升級後比對 | 隨版本 |
| T25 | `doctor` 與啟動檢查：版本不足、同步資料夾、權限異常都有明確訊息 | 模擬各種環境（替換版本回報、放進同步路徑） | 1 |

## 效能與規模

1 千、1 萬、3.6 萬筆合成資料各跑一次：存入速度、全文查詢（3 字元以上）、1–2 字元短詞掃描、分頁、標籤展開、備份與還原耗時，並記錄資料庫檔大小。首次基準值出來後，與使用者約定可接受上限；不預先編造門檻。

## 執行方式

- 快速集（每次提交前）：T01–T05、T08–T11 的小資料版與型別檢查。
- 完整集（每步驟完成、發布前）：全部加規模測試。
- 失敗故障注入與行程終止測試標記為 `slow`，不在快速集。
- 每個新功能或修正同批補對應測試；移除功能時同批更新或刪除。
