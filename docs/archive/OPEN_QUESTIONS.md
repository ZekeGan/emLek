## 不能靠工程假裝消除的限制

- 所有最新刪除／撤回狀態與獨立帳本同時遺失後，無法從舊備份推導後來發生的刪除；必須 fail closed。
- 可讀資料已傳給第三方模型後，本機無法保證平台副本刪除。
- 同 SID、管理員 Agent 或 Agent 可控制 owner 核准桌面時，不能宣稱強隔離。
- 2026-10-29 改用有限保存委派後，Core 可驗證 Agent 身分及 scope，無法僅憑 Agent 請求／訊息參照獨立證明使用者意圖；可信任 Agent 被攻陷或受注入影響時，可能在已授權範圍內誤讀／誤存。這是已知信任界限，不能虛稱已解決；最小授權、隔離、撤銷與如實稽核維持。
- 沒保存過的生活片段或外部網頁不能保證恢復；沒有完成紀錄不等於未完成。

以上不是待發明新技術解決的工作單，而是必須在產品體驗與發布報告明示的界限。

## 何時真的需要使用者決定

只有隔離部署所需的系統變更／權限、真實私人資料、獨立備份與安全帳本媒介、付費模型／外部服務、不可逆清理，或驗證後仍存在的核心體驗／安全矛盾才需要新的決定。不要在 P0 尚未提供證據前要求使用者逐項選資料庫、分詞器或 Python 套件。
